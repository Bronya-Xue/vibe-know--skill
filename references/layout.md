# 版式：先有内容，再有格子

> 这一篇解决的是"四部片看着像同一个模具"的问题。
> 如果你只做一条片子，`craft.md` 就够了；如果你做了两条以上，来这里。

## 一、为什么会做出"模板感"

不是因为偷懒，是因为把三样东西当成了可复用资产，然后所有的片子都往同一个格里塞：

| 被写死的东西 | 后果 |
|---|---|
| 一张时间表（`ch1In: 16.4, ch2In: 32.4 …`） | 每章被分配同样的秒数，不管这个话题需不需要 |
| 一组转场点（七次，半宽都是 `.42`） | 节拍能被数出来，观众感觉得到"又到点了" |
| 一个仪表位置（`K.gauge(fr, 64, 150, …)`） | 每章都要绕开左上角那个缺口，构图必然雷同 |

这三样一写死，剩下的就只能"在中间摆一坨"里微调。**版面是果，不是因。**

翻车的实证：三部片的时间表逐字节相同；布局体检扫出 12 处遮挡（公寓楼左上角被仪表压掉 240×150、
监控左上角压掉 230×100、三块底板伸进字幕带）。

## 二、正确顺序：内容 → 版式 → 秒数 → 坐标

开工时按这个顺序问自己，每一步都对上一问负责：

1. **这一章要说清哪几件事？**（不是"这章讲什么"，是"讲完观众能说出哪几句"）
2. **这几件事之间是什么关系？** 对照 / 递进 / 因果 / 反转 / 并置 —— **关系决定版式**
3. **看清它们需要几秒？** 到这里才是时间表
4. **元素往哪儿摆？** 到这里才是坐标，且必须过第三条的安全区

### 关系 → 版式 对照表

| 这一章的关系 | 版式 | 例子 |
|---|---|---|
| 一个说法和它的证伪 | **双栏并置**，中间一道线 | 1964 报纸 vs 2007 案卷 |
| 同一件事只改了一个变量 | **左右分屏**，中线就是那个变量 | 看得见 / 看不见 |
| 三个数字一路往下掉 | **阶梯下沉**，位置也降，不只是高度降 | 75% → 38% → 10% |
| 一条链断在某一环 | **横向流程占满宽**，断口物理错位 | 五步链断在第三步 |
| 同一场景的几种处理 | **同一背景多次变奏**，只有处理变 | 三招 |
| 一段流程 / 一台机器 | **满幅嵌入**，读数做成 OSD 叠在画面里 | 监控画面 |
| 一个人的处境 | **不对称构图**，主角压在分割点上，空出来的地方也是内容 | 街头的倒下的人 |

**判断标准**：把这一章的字幕拿掉，只看画面，还能不能看出这几件事之间的关系？
看不出来，就是版式没对上内容。

## 三、三条跑道（硬约束，不是建议）

```
1920 × 1080
┌──────────────────────────────────────────┐
│ 年份标签区  y 70–130                      │
│ ┌────────┐                               │
│ │ 仪表   │ x 64–410 / y 150–400          │  ← 仪表航道：内容不许进
│ │ 航道   │   （含它下面那行副标题）        │
│ └────────┘                               │
│                                          │
│    内容区：x ≥ 440 或 y ≥ 400             │
│                                          │
│                        信息底线 y ≤ 770   │
│ ─────────────────────────────────────    │  ← y ≥ 790 开始渐暗，字幕在这儿
│    字幕带（只有地面、虚化远景可以进）       │
└──────────────────────────────────────────┘
```

在 `film.js` 顶部写成常量，所有坐标引用它：

```js
const SAFE = { gr: 440, gb: 400, cb: 770, m: 120 };   // 仪表右界 / 仪表下界 / 内容底线 / 版心留白
```

然后用它推出坐标，而不是手写数字：

```js
const TOP = SAFE.gb + 10;          // 410：给仪表让出头顶那条
labRoom(fr, { x0: SAFE.gr, x1: 1780, fy: 558, top: TOP });
stage(fr, SAFE.gr, TOP, 1790, SAFE.cb, k);           // 底边压在 770，不越界
```

**唯一允许的例外**：地面、远景、虚化背景可以伸进字幕带 —— 用 `// @allow` 标出来。

## 四、自动体检，别靠眼睛

`engine/check_layout.py` 扫源码里的字面坐标，报三件事：
压仪表航道 / 伸进字幕带 / 超出版心。

```bash
python engine/check_layout.py projects/bystander          # 人读
python engine/check_layout.py projects/bystander --json   # 给脚本用
```

写完就跑，不用等渲染（9 分钟才出结果，太晚）。改一条片子前后的对比：

```
改前：12 处 —— 压仪表 6 处（最大 240×150）、伸进字幕带 3 处
改后：0 处
```

**它只扫字面量**。`lerp` / 变量算出来的坐标扫不到，那部分仍要靠抽帧 + 像素探测。
所以它是第一道网，不是唯一一道。

## 五、转场：每次压多深，按"断没断"来定

不要七次都一样。`K.dips` 只能给统一深度，自己写：

```js
const DIP = [
  [7.2,  .42, .92],   // 钩 → 片名：硬收，像翻篇
  [32.0, .40, .48],   // 知 → 形：同一条证据链，轻轻一压
  [64.0, .40, .46],   // 我 → 术：换角度，不断线
  [91.2, .46, .88],   // 最后一脚
];
function dips2(t, pts) {
  let d = 0;
  for (const p of pts) d = Math.max(d, p[2] * (1 - smooth(clamp(Math.abs(t - p[0]) / p[1]))));
  return d;                                   // 0 正常，1 全黑
}
const dim = lerp(1, .16, dips2(t, DIP));
```

## 六、衔接：让上一镜的东西接着长成下一镜

比转场更重要的是**元素接力** —— 让前后两章共用一样东西，观众才不会觉得被切了一刀。

- 片名的开头 1.5 秒，把上一章那圈围观者的影子画出来，正在往上收；
  片名里被切开的 8 片碎片，落地就变成那圈人。
- 结尾回场：开头那个道具/角色回来一次（这条 `craft.md` 也提过，这里再强调它属于衔接，不只是收束）。

实现上不需要跨章绘制：在**新章的开头**画上一章最后一个东西的简化版，正在变形/淡出即可。

## 七、时间表：每章多长，由它要讲清几件事决定

不要平均切。同样是 100 秒：

```
钩    0–7.2    短才压得住（7.2，不是 8）
片名  7.8–15.4 母题要时间展开
知    15.6–32   "传说→证伪"要叙事，给足 16.4
形    32.2–49   三次落差，16.8
我    49.2–64   五步链要展示时间，14.8
术·为什么 64.2–77   一个对照，12.8 够了
术·怎么 77.2–91     三次变奏，13.8
答    91.2–100  反转需要留白，给到 8.8 —— 这是全片最长的一章之一
```

反例：v1 把"答"压到 5.6 秒（94.4–100），反转还没落地字幕就结束了。

## 九、引擎层的 det 假阴性（这一节救过一次）

`det` 间歇挂 `15.085` 那一类时刻，**不是源码里有 `Math.random()`，是 Chrome 跨 page 启停时
GPU 命令队列的未提交像素**——下次截图拿到的还是上一帧混合后的缓存。

**症状**：同一 page 内 `seek(15.085)` 重复 3 次 hash 都稳定，但两次 `with_page` 实例间 hash 不同。

**修法**（已合进 `engine/vk.js`）：在 `seek()` 末尾 `out.drawImage` 后加一行：
```js
out.getImageData(0, 0, 1, 1);   // 强制 GPU 把这一帧的命令都提交完
```
原理：读一个像素是同步系统调用，强制 GPU flush 所有未提交的命令。
**原本 8/10 间歇失败，加上后 10/10 通过**。

`det` 本身也加了一层重试兜底（`--det` 默认 8 个 trial，不同 seed），万一还有 GPU 层抖动不会全盘错过。
但根因是上面那个 fix。

**复现路径**：写一条 `K.titleGilt`（用 `chars` + `fr.glow`），`det` 大概率会撞上 —— 因为这两条路径最依赖 GPU 复合。
